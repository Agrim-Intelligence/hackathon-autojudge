# maintain-context

> Keep the context system from becoming the noise it was built to prevent.

## Goal
Run a health pass across all context stores. Produce a maintenance report with safe-fixes applied and destructive actions proposed (never applied without approval). Each store rots differently — each gets the right treatment.

**Safety contract (non-negotiable):**
- **Archive, never delete.** Stale content moves to `archive/` subdirectory. Git preserves history. Nothing is lost.
- **Append-only is sacred.** The decision log (`docs/decisions/`) is only indexed (TOC regenerated), never trimmed.
- **Never auto-edit user-reviewed context docs** (`docs/contexts/architecture/`, `docs/decisions/`). Flag them. The user decides.
- **Destructive proposals need approval.** In `report` mode: audit + safe-fixes only. In `interactive` mode: present proposals, apply what the user approves.

## Modes

- **`report`** (default): run the full audit; apply only safe-fixes; render everything destructive as a proposal. No archiving.
- **`interactive`**: present proposals grouped by store; apply the ones the user approves.

When to use each: use `report` for a scheduled bi-weekly check. Use `interactive` when you're ready to actually clean up.

## The pass — store by store

### 1. Skill files (`.claude/skills/**`) — Agrim-specific staleness check

- **60-day staleness:** for each `SKILL.md`, check the last git commit date that touched it. Older than 60 days → flag as an improvement candidate. Append to the report: skill path, days since last update, "suggested: run `improvement-plan`".
- **Placeholder check in `when_to_use`/`description`:** any skill with `<placeholder>` text in frontmatter → flag as incomplete.
- This is `report`-only — no auto-archiving of skills.

### 2. `project-rules.md` — placeholder audit

- Scan `.claude/project-rules.md` for any unfilled placeholder token — anything matching `<...>` angle brackets (e.g. `<command>`, `<commands>`, `<name>`, `<path or ...>`, `<one line>`, `<reason>`, `<rotation link>`, `<N>`).
- **Exclude `project-rules.template.md`** — it is *supposed* to be all placeholders; never flag the template.
- Flag each hit: field name, current placeholder value, "action needed: fill in real value".
- This is the most common cold-start issue — sessions are unreliable when `project-rules.md` is still template-only.

### 3. `docs/plans/` — archive merged plans

**Safe-fix (applies in `report` mode):** create `docs/plans/ACTIVE.md` if it doesn't exist, listing plan files that appear active (created in last 30 days, or explicitly named "active").

**Proposal (needs approval in `interactive` mode):**
- Plans whose corresponding PR has merged (check `git log` for plan slug mentions) → propose moving to `docs/plans/archive/`.
- Plans older than 60 days with no recent git activity → flag as candidates for archive review.

### 4. `docs/contexts/` — staleness flags

- **Session contexts** (`docs/contexts/<slug>.md` that are NOT in the `architecture/` subfolder): older than 30 days → flag as stale. These are ephemeral; the note is informational, not destructive.
- **Architecture doc** (`docs/contexts/architecture/README.md`): older than 90 days → flag with recommendation: "run `externalize-architecture` to refresh".
- **Missing architecture doc**: if `docs/contexts/architecture/` doesn't exist → flag as "cold-start gap — run `externalize-architecture` on this repo".

### 5. `docs/decisions/` — navigability (safe-fix)

**Safe-fix:** for each `docs/decisions/YYYY-MM.md`, regenerate a TOC at the top of the file:
```markdown
<!-- TOC — auto-generated by maintain-context, do not edit manually -->
- [YYYY-MM-DD — Title 1](#yyyy-mm-dd--title-1)
- [YYYY-MM-DD — Title 2](#yyyy-mm-dd--title-2)
<!-- /TOC -->
```
This is metadata, not an ADR edit — allowed. Never edit the ADR entries themselves.

If the current month file is > ~2000 lines → recommend adding per-week `###` sub-headers going forward. Don't restructure history.

### 6. `docs/decisions/design-watches.md` — prune the register

Unlike the monthly ADR logs, this file is **editable** (watches mutate and retire). Audit it:
- **Retire-when met:** for each active watch, check whether its *retire-when* condition has shipped (e.g. the named CI gate or structural fix now exists). If so → propose moving it to the `## Retired` section with today's date and what subsumed it. *(Proposal, not safe-fix — the user confirms the condition is truly met.)*
- **Cap breach:** if active watches exceed ~12 → flag. An over-cap register stops being read. Recommend retiring the lowest-value watches or promoting them to mechanical gates.
- **Staleness:** flag any active watch whose *applies-when* hasn't matched a plan/diff in a long while as a retire candidate.
- **Hygiene:** flag any watch missing a *retire-when* (a permanent tax) or a *why* (no provenance).
- Never rewrite the *content* of a watch's rule — flag for the user.

## Output — the maintenance report

Write `docs/improvements/context-maintenance-<date>.md`:

```markdown
# Context Maintenance Report · <YYYY-MM-DD>

## Health line
Skills: <N> stale (60+ days) · project-rules: <N> unfilled fields · 
Plans: <N> active · <N> archive candidates · 
Contexts: architecture <N days old> · decisions <N month files> · 
Safe-fixes applied: <list>

## Safe-fixes applied
- [ ] docs/plans/ACTIVE.md created/updated
- [ ] docs/decisions/ TOC regenerated for <files>

## Proposed actions (need approval)
### Plans to archive
- docs/plans/<slug>.md — reason: <merged PR / 60 days inactive>

### Skills to review
- .claude/skills/<path>/SKILL.md — last updated: <date> (<N days>)

### project-rules.md gaps
- Field: <field name> — current value: `<placeholder>` — action: fill in real value

### Context staleness
- docs/contexts/architecture/README.md — last updated: <date> — action: run externalize-architecture

### Design-watches
- DW-<NN> — retire-when met (<what shipped>) → propose retire
- Register at <N> active — <within cap / OVER CAP, prune>
```

## After applying (interactive mode only)
- Append a brief entry to `docs/decisions/YYYY-MM.md` only if a structural trim happened: what was archived + why.
- Update `docs/plans/ACTIVE.md` to reflect current active plans.

## Rules

- **Recency is the tiebreaker.** Keep recent; archive old-and-completed.
- **Reversible over destructive.** Archive/move, never delete.
- **Append-only for decisions.** TOC regeneration is metadata, not editing.
- **Flag context docs; never rewrite them.** `externalize-architecture` and `record-decision` are the right tools for updating context content.
