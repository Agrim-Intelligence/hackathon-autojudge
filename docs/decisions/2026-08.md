## ADR-2026-08-10 · Retired Anthropic model + inference tool-loop resilience

**Status:** accepted · **Date:** 2026-08-10 · **Deciders:** dev.ai@agrim.ai (Chetan), Claude

### Context

`anchor-smoke`'s nightly cron had failed identically every day since at least 2026-08-01.
Root cause, confirmed by live-calling the Anthropic API directly: `claude-sonnet-4-20250514`
(the configured reasoning-tier model, `config.py`) has been retired by Anthropic — every call
returns `404 not_found_error`, with the SDK surfacing Anthropic's own deprecation notice.
This is not a CI-only problem: Railway's production `dashboard` service is configured
`primary=anthropic, fallback=groq` — the same broken model — so any submission evaluated live
would hit the identical failure.

Tracing why the (healthy) Groq fallback never saved a run: the pipeline's first reasoning-tier
call is the `inference` agent's tool-calling loop (`_run_tool_loop`,
`agents/inference.py`), which calls `llm.complete_tools()`. Unlike `complete()` (used by every
other agent via `complete_json()`), `complete_tools()` has no exception handling and no retry —
a raw call whose failure propagates straight through `run_inference()` to the orchestrator,
which records the failure and re-raises, killing the entire submission before
`code_analyst`/`browser_verifier`/`rubric_scorer` — all of which have working fallback — ever
run.

### Decisions

1. **Model swap.** `autojudge_anthropic_reasoning_model`: `claude-sonnet-4-20250514` →
   `claude-sonnet-5`. Verified live before choosing: `claude-sonnet-5` and `claude-opus-5` both
   resolve correctly; `claude-haiku-4-5-20251001` (extraction tier) was never affected. Picked
   Sonnet 5 as the like-for-like tier replacement, not the Opus upgrade, to keep behavior/cost
   close to what the anchors were calibrated against.
2. **Inference resilience via existing code, not new cross-provider tool-calling.** The
   tool-calling loop already had a documented sibling path — `_run_single_shot()` — used when the
   primary provider doesn't support tool-calling at all. It was only ever selected *statically*
   by provider, never as a *runtime* recovery. `_run_tool_loop` now catches a `complete_tools()`
   failure and falls through to `_run_single_shot(bundle)`, which already routes through
   `complete_json()` → `complete()`'s existing cross-provider fallback. The returned
   `InferredSubmission.gaps` records why the fallback fired, visible on the judge dashboard's
   Gaps panel.
3. **Explicitly not building full cross-provider tool-use parity.** Anthropic's native tool-use
   isn't portable to Groq/OpenRouter's wire format without real design work; the single-shot path
   already gives every other agent a working fallback, so replicating tool-calling elsewhere
   wasn't necessary to close the actual exposure. Scope stays surgical.
4. **No retry decorator added to `complete_tools()`.** The failure mode that caused this incident
   (a retired model ID) is deterministic — retrying the same broken model three times wastes
   time without helping. The single-shot fallback (a different provider) is the real recovery.

### Consequences

- One retired/unavailable Anthropic model can no longer take down an entire submission
  evaluation; the pipeline degrades to a (possibly gapped, judge-routed) inference and continues
  through the remaining agents, all of which have independent fallback already.
- Anchor scores may shift slightly from the model change (Sonnet 4 → Sonnet 5 is a real
  model-side change) — validated with a manual `anchor-smoke` run per the calibration invariant;
  recalibrated with evidence if drift exceeded `MAX_DRIFT`.
- No change to grounding, anti-cheat, or human-decision stickiness.
